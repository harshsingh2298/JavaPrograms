4. Bean lifecycle and scopes
Typical lifecycle:
Bean definition → Instantiation → Dependency injection → Initialization → Ready for use → Destruction
- @PostConstruct: runs after dependency injection during initialization.
- @PreDestroy: runs during normal bean destruction, such as application-context shutdown.
Default scope is singleton — one bean instance per Spring application context. Singleton does not automatically mean thread-safe.
Other scopes include prototype, request, and session.

 Revision 4 — JVM, memory and garbage collection
 
 
 1. JVM memory areas
Stack

Each thread has its own stack. It holds method frames, local variables, and references used during method execution.

Heap

Shared across threads. Objects and arrays are allocated here.

Metaspace

Stores class metadata. In Java 8 and later, it replaced PermGen.

Interview trap: Don't say every primitive variable lives on the stack. A primitive local variable may be stored in a stack frame, while a primitive instance field is part of its object on the heap.


2. Garbage collection (GC)
The garbage collector reclaims memory occupied by objects that are no longer reachable from GC roots.
Common GC roots include:
- References held by active threads and their stack frames.
- Static references associated with loaded classes.
- JNI references and other JVM-managed roots.
Important: An object being eligible for garbage collection does not mean it will be collected immediately. Calling System.gc() is only a request or hint, not a guarantee.
Also, Java can still have memory leaks: objects may remain reachable even when the application no longer needs them.


3. JVM errors to distinguish

Error	Typical cause

StackOverflowError	Excessive recursion or stack-frame growth.

OutOfMemoryError	JVM cannot satisfy a memory allocation request.

Memory leak	Unneeded objects remain reachable, causing memory usage to grow.
