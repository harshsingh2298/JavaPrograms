Annotation	Purpose
@Component	Marks a class for component scanning.
@Service	Identifies a service/business-layer component.
@Repository	Identifies a data-access component and supports persistence exception translation.
@Controller	Defines a Spring MVC controller.
@RestController	Controller whose handler return values are written to the response body by default.
@Configuration	Declares a configuration class.
@Bean	Declares a bean through a configuration method.
@Autowired	Requests dependency injection.


Important distinction: @Component is placed on a class for scanning; @Bean is placed on a method that returns an object for Spring to manage.

4. Bean lifecycle and scopes
Typical lifecycle:
Bean definition → Instantiation → Dependency injection → Initialization → Ready for use → Destruction
- @PostConstruct: runs after dependency injection during initialization.
- @PreDestroy: runs during normal bean destruction, such as application-context shutdown.
Default scope is singleton — one bean instance per Spring application context. Singleton does not automatically mean thread-safe.
Other scopes include prototype, request, and session.

Your answer has the right idea, but one correction:
 @RestController does not contain a ResponseEntity object.
 @RestController combines @Controller and @ResponseBody.
 
 Spring commonly uses an HttpMessageConverter, such as Jackson's JSON converter, to serialize the returned object.
Remember:
- @RestController → returns response bodies, commonly JSON.
- @Controller → commonly returns view names, unless response-body handling is specified.
- ResponseEntity → optionally controls the response status, headers, and body.
